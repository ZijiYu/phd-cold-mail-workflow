# Applicant profile template (`.local.md`)

The skill reads `.local.md` from the project root. Copy the block below into that file and fill it in. Keep it factual: every claim an email makes about the applicant should be traceable to a line here or to a document the user supplies.

Fields marked *optional* can be left out. Leave a field blank rather than guessing.

```markdown
# Applicant profile

## Identity
- name:
- preferred name in emails:
- current position: (e.g. "MS student in CS, <University>, expected May 2027")
- application cycle: (e.g. "Fall 2027 PhD")
- homepage:
- scholar / github: (optional)
- cv_link: (public link, or "attach")

## Research focus
- one-sentence focus: (the sentence you would say to a professor)
- sub-problems: (3-5, specific)
- methods I can execute: (concrete skills a lab would rely on)

## Projects
<!-- One block per project. Separate personal contribution from team results. -->
### <short project name>
- problem:
- my contribution: (what I personally did)
- team result: (what the project achieved overall)
- metrics: (exact numbers, with dataset/benchmark and baseline)
- status: (published at X 2026 / accepted at X 2026 / under review at X / arXiv preprint / in progress)
- my author position: (first / co-first / second / other)
- links:
- do not claim: (anything that must not be overstated, e.g. "not first author", "result is from the team's model, not mine")

## Current standing (optional)
- offers / interviews: (e.g. "verbal offer from <program>, decision due <date>")
- constraints: (regions, funding, start date, family, visa considerations you want respected)
- applications planned: (approximate number)

## Writing preferences
- tone: (e.g. "direct, no flattery")
- subject line format: (optional)
- phrases I like / phrases to avoid:
- signature block:

## Recommenders (optional)
- name, relation, institution - only if the user is happy for this to inform discovery (warm network) or be mentioned
```

## How the skill uses each section

| Section | Used in |
|---|---|
| Research focus | Discovery stage A; first sentence of the email |
| Projects | Applicant anchor; `do not claim` is a hard constraint on wording |
| Current standing | Discovery priority (raise the bar when an offer exists); funding/decision emails |
| Writing preferences | Every draft; overrides defaults except official lab instructions |
| Recommenders | Warm-network candidates in discovery; never mentioned in an email without the user's say-so |

When a request needs a missing field, ask only for that field, then offer to add the answer here.
